แผนแม่บทและขั้นตอนการดำเนินงาน
เว็บไซต์รวบรวมกฎหมายและข้อเสนอการปฏิรูปอนุบัญญัติคุรุสภา
(ระบบคลังกฎหมาย • ทะเบียนปฏิรูป • เทียบตัวบท • ผังลำดับศักดิ์ • ความเห็นกฎหมาย • ข้อเสนอการดำเนินงาน)
ฉบับวางแผนโครงการ — จัดทำ ๒๐ กันยายน ๒๕๖๙
การตัดสินใจที่ยืนยันแล้ว (กรอบโครงการ)
รูปแบบโฮสต์: เว็บไซต์แบบ Static + GitHub Pages (ไฟล์ HTML/CSS/JS + ค้นหาฝั่งผู้ใช้ ไม่มีเซิร์ฟเวอร์หลังบ้าน) — ทีมเป็นเจ้าของโค้ด ปรับแก้/ดีพลอยเองได้
กลุ่มเป้าหมาย: เครื่องมือทำงาน ภายในทีมยกร่าง (เน้นความครบถ้วน ตรวจสอบได้ อ้างอิงถึงตัวบท)
ขอบเขต v1: เริ่มที่ คอร์ปัสคุรุสภา (๑๗๒ ไฟล์ ๑๒ หมวด) ก่อน แล้วขยายสู่ กฎหมายหลัก/กฎหมายหลักการศึกษา ใน v2
ฟีเจอร์ v1 (ครบทุกข้อที่เลือก): (๑) คลังกฎหมาย + ค้นหา/กรอง (๒) ทะเบียนสถานะปฏิรูป คงไว้/แก้ไข/ยกเลิก (๓) เทียบตัวบท เดิม↔ข้อเสนอใหม่ (๔) ผังลำดับศักดิ์ + ความเห็นกฎหมาย (๕) ข้อเสนอการดำเนินงานที่จำเป็นปัจจุบัน/อนาคต

ภาพรวมคอร์ปัสที่สำรวจแล้ว (ฐานข้อมูลตั้งต้น)
กฎหมายคุรุสภา — ๑๗๒ ไฟล์ / ~๑๘๑MB / ๑๒ หมวด (รธน.–พ.ร.บ., กฎกระทรวง, ข้อบังคับ, ระเบียบ, ประกาศ, คำสั่ง/มติ, ประมวลจริยธรรม, คู่มือ, แผน/สถิติ, แบบฟอร์ม) + เอกสารส่งมอบของโครงการ ๑๖ ชิ้น
กฎหมายหลัก — ๕๕ ไฟล์ / ~๔๕MB (รธน.๒๕๖๐, ประมวลอาญา, พ.ร.ฎ.บ้านเมืองที่ดี/มอบอำนาจ, พ.ร.บ.ระเบียบบริหารราชการแผ่นดิน, ศาลปกครอง, ป.ป.ช., ยุทธศาสตร์ชาติ, ธรรมาภิบาล) — มี .txt ถอดข้อความแล้วจำนวนมาก
กฎหมายหลักการศึกษา — ๗๒ ไฟล์ / ~๑๖๘MB (พ.ร.บ.การศึกษาแห่งชาติ, ระเบียบบริหาร ศธ., คำสั่ง คสช.๑๗/๑๙-๒๕๖๐, แผนการศึกษาแห่งชาติ, กยศ./กสศ., คนพิการ, โรงเรียนเอกชน)
รวม ~๒๙๙ ไฟล์ / ~๓๙๔MB (PDF ~๒๑๑, .txt ถอดข้อความ ~๕๘) — พบไฟล์ซ้ำข้ามโฟลเดอร์ (รธน.๒๕๖๐, ประมวลอาญา, ยุทธศาสตร์ชาติ ฯลฯ) ต้องทำ dedup + กำหนดฉบับหลัก

๑. สถาปัตยกรรมโดยรวม
ใช้แนวทาง “แยกข้อมูลออกจากหน้าเว็บ” (data-driven static site) กล่าวคือ แปลงเอกสารกฎหมายทั้งหมดให้เป็น ชุดข้อมูล JSON ที่มีโครงสร้าง (แคตตาล็อก + ตัวบท + ทะเบียน + ดัชนีค้นหา) แล้วให้หน้าเว็บ HTML อ่านข้อมูลนั้นมาแสดง/ค้นหา ที่ฝั่งเบราว์เซอร์ผู้ใช้ จึงไม่ต้องมีเซิร์ฟเวอร์/ฐานข้อมูลหลังบ้าน เหมาะกับ GitHub Pages และทำให้ทีมปรับปรุงข้อมูลได้โดยแก้ไฟล์ JSON แล้ว commit
ข้อดี: (ก) ฟรี เสถียร โหลดเร็ว (ข) โค้ดและข้อมูลอยู่ใน Git ตรวจประวัติย้อนหลังได้ทุกการแก้ (versioning) เหมาะกับงานกฎหมายที่ต้องตรวจสอบได้ (ค) ค้นหาเต็มข้อความได้โดยไม่ต้องมีเซิร์ฟเวอร์ (ดัชนีสร้างล่วงหน้า) (ง) แยกงาน “ทำข้อมูล” ออกจาก “ทำหน้าเว็บ” ให้ทำคู่ขนานได้
ข้อพึงระวังสำคัญ — การจำกัดการเข้าถึง (Internal tool vs GitHub Pages)
GitHub Pages แบบมาตรฐาน เปิดเป็นสาธารณะ ทุกคนที่มีลิงก์เข้าถึงได้ แต่เว็บนี้เป็น “เครื่องมือภายในทีมยกร่าง” และมี ข้อเสนอ/ความเห็นก่อนการตัดสินใจ ที่อาจยังไม่ควรเปิดสู่สาธารณะ
ทางเลือกจำกัดการเข้าถึง (เลือก ๑): (ก) Repo ส่วนตัว + GitHub Pages แบบ Private (ต้องใช้แผน GitHub Team/Enterprise) (ข) ย้ายโฮสต์ไป Cloudflare Pages/Netlify + ตั้งรหัสผ่าน/Access (ยังฟรีและตั้ง gate ได้) (ค) ยอมรับสาธารณะแต่ แยกชั้นข้อมูล — เผยเฉพาะตัวบทกฎหมาย (ข้อมูลสาธารณะอยู่แล้ว) และกันส่วนข้อเสนอ/ความเห็นไว้เป็นไฟล์แยกที่ไม่ deploy
ข้อเสนอ: เริ่มพัฒนาบน repo ส่วนตัว, ระยะทดสอบใช้ Cloudflare Pages/Netlify + รหัสผ่าน; เมื่อพร้อมเผยแพร่ตัวบทสู่สาธารณะค่อยเปิด GitHub Pages เฉพาะชั้นข้อมูลสาธารณะ

๓.๒ แฟ้มข้อมูลอื่น
• data/instruments/<id>.json — ตัวบทมีโครงสร้างรายมาตรา/หมวด/ข้อ (เฉพาะฉบับที่ตรวจทานแล้ว เช่น พิจารณาฯ ๒๕๖๘, มาตรฐานวิชาชีพ, สรรหาเลขาธิการ, รับรองความรู้ฯ) — ใช้ข้อมูลทองจากงานที่เราตรวจทานไว้แล้ว
• data/register.json — ทะเบียนปฏิรูป (ก-๑…ก-๙, ข-, ค-, ง-) พร้อมสถานะ คงไว้/แก้ไข/ยกเลิก/ตรวจสอบ/ดำเนินการแล้ว + ฐานอำนาจ + เหตุผล → ป้อนหน้าทะเบียน
• data/hierarchy.json — ความสัมพันธ์ลำดับศักดิ์ รธน.→พ.ร.บ.→ข้อบังคับ→ระเบียบ/ประกาศ + จุดที่อาจขัด/แย้ง → ป้อนผังลำดับศักดิ์
• data/opinions.json — สารบัญความเห็นกฎหมาย/บันทึกตรวจสอบ (เช่น อุทธรณ์ฯ vs ๒๕๖๘) เชื่อมกับฉบับที่เกี่ยวข้อง
• data/compare/<id>.json — คู่ “ตัวบทเดิม ↔ ข้อเสนอใหม่” รายข้อ → ป้อนหน้าเทียบตัวบท
• data/proposals.json — ข้อเสนอการดำเนินงานปัจจุบัน/อนาคต (งานเร่งด่วน/กลาง/เฝ้าระวัง + สถานะ)
• data/search-index.json — ดัชนีค้นหาเต็มข้อความ (สร้างจากตัวบท + เมทาดาทา ด้วย MiniSearch)

๔. ไปป์ไลน์จัดทำข้อมูล (Data Pipeline)
ขั้นตอนแปลงไฟล์ ~๓๐๐ ไฟล์ ให้เป็นชุด JSON ทำเป็นสคริปต์อัตโนมัติ (รันซ้ำได้เมื่อมีกฎหมายใหม่)
(๑) สำรวจและจัดทำแคตตาล็อก (inventory): เดินไฟล์ทั้ง ๓ โฟลเดอร์ → สร้าง catalog.json ตั้งต้น (ดึงชื่อ/ประเภท/ปีจากชื่อไฟล์และหมวดโฟลเดอร์) + ทำ dedup ไฟล์ซ้ำข้ามโฟลเดอร์ (กำหนดฉบับหลัก + ระบุที่อยู่สำรอง)
(๒) สกัดข้อความ ๓ ชั้น (text extraction):
(ก) ไฟล์ที่มี .txt ถอดข้อความคู่แล้ว (กฎหมายหลัก/หลักการศึกษาส่วนใหญ่) → ใช้ได้ทันที
(ข) PDF ที่ pdftotext อ่าน Unicode ได้ → สกัดตรง
(ค) PDF ฟอนต์เก่า/cmap พัง หรือสแกน (พบมากในคอร์ปัสคุรุสภา) → OCR (pdftoppm+tesseract) หรืออ่านด้วย vision — ทำเครื่องหมายว่า “ยังไม่ตรวจทาน” จนกว่าจะสอบกับราชกิจจาฯ
(๓) เสียบข้อมูลทองที่ตรวจทานแล้ว: ฉบับที่โครงการทำไว้ (พิจารณาฯ ๒๕๖๘, มาตรฐานวิชาชีพรวม, สรรหาเลขาธิการรวม, รับรองความรู้รวม) ใช้เป็นตัวบทมีโครงสร้างระดับข้อ (คุณภาพสูงสุด)
(๔) แปลงทะเบียน/ความเห็น: เปลี่ยนทะเบียน #8 และบันทึกความเห็นเป็น register.json / opinions.json / proposals.json
(๕) สร้างดัชนีค้นหา: รวมข้อความ+เมทาดาทา → search-index.json (MiniSearch)
(๖) ตรวจสอบคุณภาพ (validation): รายงานไฟล์ที่ยังไม่มีข้อความ/ยังไม่ตรวจทาน/เมทาดาทาขาด เพื่อไล่เก็บ
นโยบายความถูกต้อง (สำคัญต่อความน่าเชื่อถือ)
ทุกระเบียนต้องมี ธงสถานะข้อความ: “ตรวจทานกับราชกิจจาฯ แล้ว” / “ถอดอัตโนมัติ–ยังไม่ตรวจทาน” และแสดงบนหน้าเว็บให้ผู้ใช้เห็นเสมอ — สอดคล้องหลักการโครงการที่ห้ามนำเสนอตัวเลข/ตัวบทที่ยังไม่ยืนยันว่าเป็นทางการ
เก็บ ลิงก์/เลขราชกิจจาฯ ของทุกฉบับ เพื่อให้ตรวจกลับต้นทางได้

๕. โครงสร้างเว็บและฟีเจอร์ (Site Map)
หน้า
สาระ/ฟีเจอร์

หน้ารายฉบับ
เมทาดาทา, ฐานอำนาจ, สายวิวัฒน์ (ยกเลิก/แก้ไขโดย), ตัวบท/สรุป, ธงตรวจทาน, ลิงก์ดาวน์โหลด/ราชกิจจาฯ, ฉบับที่เกี่ยวข้อง

๘. ประเด็นที่ต้องตัดสินใจก่อนเริ่ม (Open Decisions)
(๑) การจำกัดการเข้าถึง: repo ส่วนตัว + Pages แบบ private (GitHub Team) / Cloudflare Pages–Netlify + รหัสผ่าน / หรือเปิดสาธารณะเฉพาะชั้นตัวบท (ดูกล่องแดง ข้อ ๑) — แนะนำ Cloudflare Pages + รหัสผ่านในระยะพัฒนา
(๒) ที่เก็บไฟล์ PDF (~๓๙๔MB): (ก) ใส่ใน repo ตรง ๆ (เสี่ยงขนาดใหญ่) (ข) ใช้ Git LFS (ค) ลิงก์ไปราชกิจจาฯ/ต้นทาง แล้วเก็บเฉพาะข้อความ+ไฟล์สำคัญ — แนะนำ (ค)+(ข) ให้ repo เบา
(๓) บัญชี/ชื่อ repo และโดเมน: ใช้บัญชี GitHub ใด ชื่อ repo อะไร ต้องการ custom domain หรือไม่
(๔) ขอบเขตการค้นเน็ตเพิ่ม: ให้ค้นระเบียบ/ประกาศ/กฎหมายที่ยังไม่มีในโฟลเดอร์เพิ่มหรือไม่ (เช่น กฎกระทรวง/ประกาศ ศธ. ที่เกี่ยวข้อง) — ทำใน v2
(๕) การดูแล/อัปเดต: ใครเป็นผู้เพิ่มกฎหมายใหม่ (แก้ JSON แล้ว commit) — จัดทำคู่มือสั้นในเฟส ๕

๙. ขั้นตอนถัดไปทันที (เมื่ออนุมัติ)
ผมพร้อมเริ่ม เฟส ๑ ได้ทันทีในเครื่องมือคลาวด์ (มี Python/Node ครบ) โดยจะ:
๑) สร้างสคริปต์ไปป์ไลน์ + เดินสำรวจคอร์ปัสคุรุสภา ๑๗๒ ไฟล์ → ออก catalog.json + register.json + รายงานคุณภาพข้อความ (ระบุไฟล์ที่ต้อง OCR/ตรวจทาน)
๒) วางโครง repo (โฟลเดอร์ + หน้า HTML ว่างพร้อมสไตล์ + ฟอนต์ไทย) เป็น โครงเว็บ v1
๓) ทำ ต้นแบบหน้าคลัง+ค้นหา ที่อ่าน catalog.json ได้จริง ให้เห็นภาพ แล้วส่งให้ทดลอง
ผมจะส่งมอบทั้งหมดเป็นโฟลเดอร์โปรเจกต์ในเครื่องคุณ (เช่น ~/Documents/kurusapha-law-site) พร้อมคำสั่งเปิดทดสอบและขั้นตอน push ขึ้น GitHub — หากต้องการ ผมช่วยดันขึ้น GitHub และตั้ง Pages ให้ด้วยเมื่อคุณให้สิทธิ์/บัญชี

สรุปเพื่อการตัดสินใจ
