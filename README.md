# คลังกฎหมายคุรุสภา

เว็บไซต์สาธารณะสำหรับค้นคว้ากฎหมายที่เกี่ยวกับคุรุสภา วิชาชีพครู ผู้บริหาร บุคลากรทางการศึกษา และสำนักงานเลขาธิการคุรุสภา พร้อมทะเบียนประเด็นทบทวนและกรอบวิเคราะห์ทางกฎหมาย

เว็บไซต์: https://burapatis.github.io/kurusapha-law-site/

## หลักสำคัญ

- แยก **สถานะทางกฎหมาย** ออกจาก **สถานะข้อเสนอ** อย่างชัดเจน
- เอกสารใหม่มีสถานะเริ่มต้นเป็น `unverified` ไม่อนุมานว่าใช้บังคับจากชื่อไฟล์
- รายการที่จะระบุว่าใช้บังคับ แก้ไขแล้ว หรือยกเลิกแล้ว ต้องมีเหตุผล วัน และผู้ตรวจ
- รวมไฟล์ซ้ำด้วย SHA-256 แต่เก็บแหล่งที่มาทุกคลัง
- กันไฟล์ที่ระบุว่ามีข้อมูลส่วนบุคคลออกจากแคตตาล็อกและดัชนีค้นหา
- ข้อความสกัด/OCR ใช้ช่วยค้นหาเท่านั้น ไม่ใช้แทนต้นฉบับทางการ
- ไม่รวมร่าง บันทึกภายใน และไฟล์ส่งมอบในเว็บสาธารณะโดยค่าเริ่มต้น

อ่านคำอธิบายสำหรับผู้ใช้ได้ที่ [methodology.html](methodology.html)

## แหล่งข้อมูลในเครื่อง

ตัวสร้างแคตตาล็อกอ่านสามโฟลเดอร์โดยค่าเริ่มต้น:

1. `/Users/com/Documents/กฎหมายคุรุสภา`
2. `/Users/com/Documents/กฎหมายหลัก`
3. `/Users/com/Documents/กฎหมายหลักการศึกษา`

ไฟล์เว็บไซต์ภายในโฟลเดอร์แรกจะถูกข้ามโดยอัตโนมัติ และไม่มีการแก้ไขไฟล์ต้นฉบับ

## เปิดทดสอบ

วิธีแนะนำ—เปิดพร้อมปุ่มเข้าถึงไฟล์ต้นฉบับในสามคลัง:

```bash
python3 tools/serve_local.py
```

จากนั้นเปิด http://127.0.0.1:8080/ เซิร์ฟเวอร์นี้รับการเชื่อมต่อจากเครื่องเดียว และเปิดได้เฉพาะเอกสารที่มี id ใน `data/catalog.json`

หากต้องการดูเฉพาะเว็บไซต์โดยไม่เปิดไฟล์ต้นฉบับ:

```bash
python3 -m http.server 8080
```

จากนั้นเปิด http://localhost:8080/

## สร้างข้อมูลใหม่

```bash
python3 tools/gen_catalog.py
python3 tools/validate_data.py
node --check assets/js/app.js
```

ระบุคลังเองได้โดยใช้ `--root` ซ้ำหลายครั้ง ส่วน `--include-internal` มีไว้สำหรับการทดสอบในเครื่องและไม่ควรใช้กับงานเผยแพร่สาธารณะ

## โครงสร้างสำคัญ

- `data/catalog.json` — เมทาดาทา สถานะการตรวจ แหล่งที่มา และ SHA-256
- `data/search-index.json` — ข้อความสำหรับค้นหาเฉพาะรายการสาธารณะ
- `data/register.json` — ทะเบียนประเด็นทบทวน (ไม่ใช่สถานะใช้บังคับ)
- `data/proposals.json` — ข้อเสนอ เหตุผล หลักฐาน เกณฑ์ และผลกระทบ
- `data/opinions.json` — ประเด็นกฎหมายแบบ Issue–Rule–Analysis–Conclusion
- `tools/gen_catalog.py` — รวมสามคลัง ตัดสำเนาซ้ำ และสร้างข้อมูล
- `tools/serve_local.py` — เปิดเว็บไซต์ภายในเครื่องและให้หน้ารายฉบับเปิดไฟล์ต้นฉบับจากคลังได้อย่างจำกัดขอบเขต
- `tools/validate_data.py` — ตรวจ JSON สถานะ หลักฐาน ดัชนี และลิงก์ภายใน
- `tools/cleanup_sources.py` — ตรวจไฟล์ซ้ำด้วย SHA-256 และย้ายสำเนาซ้ำ/ไฟล์อ่อนไหวไปยังพื้นที่สำรองแบบกู้คืนได้
- `.github/workflows/validate.yml` — ตรวจอัตโนมัติทุก push/pull request

## การเพิ่มสถานะที่ตรวจยืนยันแล้ว

แก้ `VERIFIED_OVERRIDES` ใน `tools/gen_catalog.py` โดยอย่างน้อยต้องมี:

- `status`
- `verificationStatus: reviewed`
- `verifiedAt`
- `verifiedBy`
- `statusBasis`
- `officialUrl` เมื่อตรวจพบลิงก์ตรงของฉบับนั้น (ห้ามใช้หน้าแรกแทน)

จากนั้นรันตัวสร้างและตัวตรวจทุกครั้ง

## การอ้างสำเนาในคลัง

หน้ารายฉบับสร้างข้อความอ้างอิงที่ประกอบด้วยชื่อเอกสาร คลัง พาธสัมพัทธ์ วันตรวจ และ SHA-256 ให้คัดลอกได้ หากยังไม่มีลิงก์ทางการ ระบบจะระบุว่าเป็น “สำเนาในคลัง” โดยไม่เรียกว่าเป็นต้นฉบับทางการ

เว็บไซต์บน GitHub Pages ไม่สามารถอ่านไฟล์จาก `/Users/...` ได้ ปุ่ม “เปิดไฟล์ต้นฉบับในเครื่อง” จึงปรากฏเฉพาะเมื่อเปิดด้วย `tools/serve_local.py` เท่านั้น สำหรับไฟล์ที่ต้องการเผยแพร่สาธารณะเป็นรายฉบับ ให้วางสำเนาที่ผ่านการตรวจแล้วไว้ที่ `documents/<document-id>.<ext>` แล้วรัน `tools/gen_catalog.py` เพื่อสร้าง `publicCopyUrl` อัตโนมัติ ห้ามคัดลอกร่าง เอกสารภายใน ข้อมูลส่วนบุคคล หรืองานที่สิทธิการเผยแพร่ไม่ชัดเจนขึ้น GitHub

## ข้อจำกัด

ฐานข้อมูลนี้ไม่ใช่ราชกิจจานุเบกษาและไม่ใช่คำปรึกษากฎหมาย ข้อสรุปที่มีผลต่อสิทธิ หน้าที่ วินัย ใบอนุญาต หรือองค์ประกอบองค์กร ต้องตรวจต้นฉบับทางการและผ่านการรับรองจากผู้รับผิดชอบก่อนนำไปใช้
